# Muse 吧唧 v1.2.5（ESP32-S3-Touch-AMOLED-1.75C）

**v1.2.5 修复（录音圆断续/空白条、信息页闪烁）**：两个毛病同源——整屏
每秒全量重绘。录音屏原先每秒整屏重画一次（擦黑+重画），圆圈描边又用了
逐点画法（这块屏会丢点），所以圆断续、带空白条、还闪；信息页原先每秒
整页重绘刷新电量，必然闪。本版改为局部更新：录音屏静态层（红点/停止
圆/文字）只在亮屏时画一次，停止圆的白边改两层实心圆叠画，每秒只重画
计时数字一条；信息页改为每 5 秒检查、只有数值变了的行才重画那一行。
菜单页底部版本号为灰色小字 v1.2.5。

**v1.2.4 修复（点进去不对版/混乱）**：
- **触摸校准（首次开机自动出现）**：刷入后第一次开机，动画之前会先出现
  「触摸校准 / 点圆圈」页，依次点 4 个红圈的中心即可。固件会自己算出这块
  屏的触摸轴向（交换/镜像/缩放）和偏移并存下来，以后开机不再出现；点错
  会显示「失败」并重来。校准页按任意侧键可跳过本次（用原始坐标）。
  之后想重校：菜单 → 信息 → 「触摸校准」。
- **点按高亮**：点中哪个按钮，哪个先变亮 0.15 秒再执行，眼见为实。
- **手选表情保持 20 秒**：在表情页或用 BOOT 键手动选的表情，20 秒内不被
  「有人说话/大音量」的自动表情覆盖（命令词照常优先）。
- **页面停留 6 秒 → 15 秒**：菜单/子页面不再动不动自己退回动画。
- 菜单页底部版本号为灰色小字 v1.2.5。

**v1.2.3 修复（菜单文字不显示）**：中文标签原用逐点 drawPixel 画，而这块
QSPI CO5300 屏会丢弃单像素写；v1.2.3 起文字改成内存拼整条 RGB565 位图
一次性刷屏（与动画同一条路径）。

**前版修复（针对 v1.2 刷入后黑屏）**：
- **显示优先启动**：开机先初始化屏幕并显示第一帧动画，触摸、音频和
  语音监听都排在出图之后启动，任何一步出问题都不会再让屏幕全黑。
- **SR 延迟初始化**：语音监听改为开机约 3 秒后在后台低优先级任务里
  启动，且初始化每一步都做了失败检查；失败只丢监听功能，动画、
  录音、推流不受影响。
- **启动循环自愈**：固件会数连续启动次数，稳定运行 30 秒清零；
  若连续 3 次启动不稳定，本次开机自动跳过语音监听，保证最坏情况
  也只是“没有监听”，不会黑屏到底。
- 其余功能与 v1.2 完全一致（录音、推流、配网、触摸 UI、命令词表）。

v1.2 新增：**待机本地监听**（不用联网，板子自己听声音变表情＋中文命令词）、
**触摸菜单**。录音仍是 Opus＋边录边传，但因为要给语音模型腾地方，
存储从约 24MB 缩到约 20MB，**单段录音上限约 1.4 小时**（v1.1 是 2 小时）。

从 v1.1 升级：直接跑下面的烧录即可，**已配好的 Wi-Fi 不用重配**
（烧录不动保存凭据的分区）。

## 一、烧录

1. USB-C 数据线把板子接上 Mac。
2. 在本文件夹打开终端，运行：`bash flash.sh`
3. 烧完板子自动重启。

## 二、首次开机：配网（只做一次；v1.1 升上来跳过）

1. 屏幕显示 SETUP 时，用手机或 Mac 连 Wi-Fi 热点 **MuseBadge-Setup**。
2. 浏览器打开 **192.168.4.1**，填家里/办公室的 Wi-Fi 名和密码，点保存。
3. 板子自动重启并连上你的 Wi-Fi，吉祥物动画出现即完成。

之后换网络：开机时按住 BOOT 键约 2 秒清除配网信息；或在
信息页点「重新配网」。（密码只存在板子里，不经过任何服务器。）

## 三、触摸操作（新）

- **点屏幕任意处** → 打开菜单（6 秒不操作自动返回动画）：
  - **录音**：开始录音（等同长按 BOOT）。
  - **表情**：6 个表情列表，点哪个就切到哪个当待机表情。
  - **信息**：电量、存储剩余、可录时长、Wi-Fi 名和 IP；
    可调亮度（＋/－），可「重新配网」（清凭据重启进配网模式）。
  - **返回**：回动画。
- **录音中**：屏幕上有红色大「停止」按钮，点它停录；
  熄屏后点屏幕任意处也能唤醒查看（与短按 BOOT 并存）。

## 四、待机监听（新，纯本地、不联网）

不录音时，麦克风在待机监听（声音不保存、不上传，只在板子上判断）：

- **有人说话** → 切「等帮手」倾听表情；停说 2 秒后回待机。
- **突然的大声响**（拍桌子、大笑）→ 「庆祝」表情闪 2 秒。
- **命令词**（说清楚、离板子别太远）→ 切对应表情并保持 6 秒：

  | 你说 | 它变 |
  | --- | --- |
  | 开始工作 | 工作 |
  | 开始干活 / 开工啦 | 做东西 |
  | 让我想想 | 连接中（先当“思考”用） |
  | 干得漂亮 / 太棒了 | 庆祝 |
  | 等一下 | 等帮手 |
  | 休息一下 | 待机 |

- 打开菜单点选时，监听不会乱切表情；回动画后恢复。
- 开始录音时监听自动暂停，录音结束自动恢复。

## 五、录音（与 v1.1 相同，上限有变）

- **长按 BOOT（1.2 秒）** 或菜单点「录音」：开始录音；长按或点屏上
  「停止」按钮结束。
- 录音开始 3 秒后**屏幕自动熄灭**；录音中短按 BOOT 或点屏幕可亮屏
  查看 3 秒（显示 streaming / local only）；到 **约 1.4 小时**自动停；
  存储快满也会自动停。
- 录音格式：Opus 16kbps，本地存为 `.ogg` 主本。

## 六、边录边传（Mac 接收端，与 v1.1 相同）

1. Mac 和吧唧连同一个 Wi-Fi。
2. 在 Mac 终端运行：`python3 badge_receiver.py`，保持窗口开着。
3. 吧唧一开始录音就会自动找到接收端并实时推流；录完的文件在
   `~/Downloads/muse-badge-recordings/`，是标准 `.ogg`，可直接播放。
4. 如果装了「吧唧录音库 BadgePod」，录完的文件会自动投进它的收件箱，
   自动转写、生成纪要。
5. 接收端没开也没关系：吧唧本地主本照常录，只是没有实时副本
   （屏幕显示 local only）。

## 七、这次要验的点

先沿用 v1.1 的验收清单（动画颜色、BOOT、录音音质、电量、配网、
熄屏、推流），另外加 v1.2 新项：

1. 点屏是否出菜单，四个按钮点按是否准（位置有没有偏）。
2. 菜单里的表情页、信息页显示是否正确；亮度＋/－是否有效。
3. 待机时对它说话，是否切倾听表情；停说后是否回待机。
4. 命令词逐个试（上表 8 句），记下哪句不灵、哪句会误触发。
5. 录音屏上的「停止」按钮是否好用；录音后监听是否恢复。

## 已知边界

- 录音导出仍只有边录边传这一条路；没传成的录音留在吧唧本地，
  暂时没有补传功能（本地主本不会丢）。
- 两次录音之间请隔几秒再开始，上一段的推流收尾更干净。
- 命令词只认上表 8 句、且要在相对安静的环境；
  误触发率和识别距离需实测后调阈值。
- 「思考」暂时用连接中表情占位。
- 与 Muse 实时状态联动不在本版范围。

## v1.2.5 动画更换
6 个状态动画已全部换成 Muse App 头像当前呈现的版本（与助理在本 App 里干活/待机时显示的动画同源），不再使用早先单独生成的那批。对应关系：idle/connecting=待机、working/waiting-helper=戴耳机敲笔记本、making=捧光球、celebration=举手庆祝（星星）。固件程序与 v1.2.1 完全一致，仅动画素材不同。
